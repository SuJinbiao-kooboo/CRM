# 微信自动化服务器迁移手册

> 适用范围：RuoYi-Vue 微信询报价自动化项目从旧服务器迁移到新服务器。
> 执行原则：先停写、再迁移、先验证、最后开启自动发送。
> 迁移日期：2026-11-05
> 最后复核：2026-11-10（本机实测：消息读取正常，文件传输助手单发成功）

---

## 1. 五条硬约束

1. **微信客户端、微信数据目录、`wx_gateway.py`、Java 后端必须在同一台 Windows 主机上运行。**
   Java 通过 `ProcessBuilder` 调用本机 Python；后端换到另一台机器后，不能直接读取原机器的微信数据库。
2. **同一时间只能有一套后端和网关写业务库。** 旧机器和新机器同时运行，会造成重复采集、重复生成任务甚至重复发送。
3. **换机器后微信本地库的 `real_sender_id` 不能直接复用。** 业务库 `wechat_message.sender` 可以完整迁移；微信分片库里的发送人 rowid 只能在新机器上重新解析。
4. **迁移期间必须先关闭自动发送。** `autoSendEnabled` 保持 `false`，确认消息、分类、录入、任务都正常后，最后再打开。
5. **生产主机只登录一个微信账号。** 当前 Java 调用网关没有传入 `--account`，多账号环境可能自动选中错误账号。当前自动发送账号为 `Eke`。

推荐架构：

```text
新 Windows 主机
  ├─ 微信桌面版 4.1.15.13（已登录指定账号，主窗口保持可见）
  ├─ C:\Software\Python\python.exe（64 位，安装 wechatauto-replica）
  ├─ C:\Project\RuoYi-Vue\wechat-gateway\wx_gateway.py
  ├─ ruoyi-admin.jar（8081）
  └─ 前端 dist / Nginx（如需）
          │
          └──────────────> MySQL crm_me
```

## 2. 迁移前：记录现状并冻结写入

### 2.1 记录旧环境信息

迁移前在旧库执行并保存结果：

```sql
SELECT job_id, job_name, status, cron_expression, allowed_ips
FROM sys_job
WHERE job_group IN ('WECHAT', 'SYSTEM')
ORDER BY job_id;

SELECT dict_label, dict_value
FROM sys_dict_data
WHERE dict_type = 'wechat_analysis_config'
ORDER BY dict_sort, dict_code;

SELECT config_key, config_value
FROM sys_config
WHERE config_key LIKE 'sys.ai.%'
   OR config_key IN ('offer.price.advantage.threshold', 'offer.good.push.last.signature');
```

同时记录：

- 旧机器内网 IP、后端端口（当前为 `8081`）、前端端口或域名。
- 微信版本、登录账号、微信数据目录。
- Python 路径、项目路径、媒体目录。
- 旧机器上运行的 Java 进程、Python `listen` 进程和所有计划任务。

### 2.2 备份数据库

迁移数据库时使用完整逻辑备份，不建议只导出部分业务表：

```powershell
mysqldump.exe -h 42.194.240.191 -P 3306 -u root -p `
  --single-transaction --routines --triggers --events `
  --default-character-set=utf8mb4 crm_me `
  > C:\backup\crm_me_before_wechat_migration_20261105.sql
```

如果新机器继续连接原来的 MySQL，仍建议执行本步骤作为回滚点。

### 2.3 备份应用文件

至少备份：

- `ruoyi-admin\target\ruoyi-admin.jar`
- `ruoyi-ui\dist\`（生产前端）
- `ruoyi-admin\src\main\resources\application.yml`
- `ruoyi-admin\src\main\resources\application-druid.yml`
- `wechat-gateway\media\`（历史图片/文件仍需查看时）
- `wechat-gateway\wx_gateway.py` 和 `wechat-gateway\README.md`

### 2.4 关闭自动写入和发送

顺序不能反：

1. 在“微信询报价任务”页面关闭“自动发送”。
2. 在“微信消息”页面关闭“自动分类”和“自动录入”。
3. 在“系统监控 → 定时任务”暂停所有 `WECHAT` 任务。
4. 停止旧服务的 Java 进程和任何 `listen` Python 进程。
5. 确认旧服务端口已没有监听，再开始新机器操作。

用 SQL 暂停全部微信任务（`status=1` 表示暂停）：

```sql
UPDATE sys_job
SET status = '1'
WHERE job_id IN (100, 101, 102, 103, 104, 105, 106, 108);
```

同时确认：

```sql
SELECT dict_label, dict_value
FROM sys_dict_data
WHERE dict_type = 'wechat_analysis_config'
  AND dict_label IN ('autoSendEnabled', 'autoTaskGenerateEnabled', 'offerEntryEnabled', 'classifyEnabled');
```

迁移和验收期间至少保证 `autoSendEnabled=false`。不要把旧服务的进程留在后台，也不要让旧网关继续监听。

## 3. 新服务器环境准备

### 3.1 安装微信和 Python

1. 安装微信桌面版 **4.1.15.56**（当前生产机实测版本；`wechatauto-replica` 1.2.9 已适配 4.1.15.53/56）。登录固定账号，保持主窗口可见、不要最小化。
2. 安装 **64 位 Python**，默认路径：`C:\Software\Python\python.exe`。
   - **需要完整 OCR 发送能力（推荐）**：使用 Python **3.12**。`winsdk` 只有 cp312 预编译轮子，Python 3.13+ 无法安装。
   - **只做 UIA 发送 / 只拉消息**：Python 3.13/3.14 也能运行，但没有 OCR 兜底；UIA 打不开的会话会失败。
3. 安装网关依赖：

```powershell
# Python 3.12（推荐，含 OCR）
C:\Software\Python\python.exe -m pip install -U wechatauto-replica==1.2.9
C:\Software\Python\python.exe -m pip show wechatauto-replica

# Python 3.13+（无 winsdk，只走 UIA）
C:\Software\Python\python.exe -m pip install -U wechatauto-replica==1.2.9 --no-deps
C:\Software\Python\python.exe -m pip install uiautomation pywin32 pyperclip Pillow psutil colorama cryptography imageio-ffmpeg zstandard pyautogui opencv-python
```

4. 校验依赖：

```powershell
C:\Software\Python\python.exe -m pip check
```

Python 3.12 应无缺失；Python 3.13+ 只会提示 `winsdk` 缺失，这是预期行为，网关会自动关闭 OCR。

5. 确认微信和 Python 是同一 Windows 用户、同一权限级别。微信若以管理员运行，Python 也要用管理员权限运行。
   在 Codex 沙箱用户下执行 `whoami` 可能报“未检测到 Weixin.exe”，这是执行身份与微信登录用户不同，不是依赖问题。

### 3.2 复制代码并确认路径

推荐把项目放在与原机器相同的路径：

```text

```

如果新机器路径不同，必须在 `application.yml` 中增加或修改：

```yaml

  script: C:/Project/RuoYi-Vue/wechat-gateway/wx_gateway.py
  media:  C:/Project/RuoYi-Vue/wechat-gateway/media
```

当前 `application.yml` 已显式配置 `wechat:` 块，默认指向 `C:/Software/GPT/CRM/wechat-gateway/`。路径不同时改这里，或用环境变量 `WECHAT_PYTHON` / `WECHAT_SCRIPT` / `WECHAT_MEDIA` 覆盖；不能只复制代码不修改路径。

同时确认：

- `ruoyi.profile` 指向新机器实际的上传目录。
- `spring.datasource.druid.master` 指向正确的 MySQL。
- 飞书 `feishu.app-secret` 等敏感配置使用环境变量或新机器正式配置。
- `wechat-gateway\media` 目录对后端进程可读写。

### 3.3 媒体文件路径

`wechat_message.media_path` 保存的是绝对路径。如果新机器保持相同的 `C:\Project\RuoYi-Vue\wechat-gateway\media` 路径，直接复制旧 media 目录即可。若路径改变，历史消息中的旧路径不会自动变化，需要同步更新数据库中的路径前缀；否则老图片/文件详情可能打不开。

### 3.4 网关单独自检

在项目根目录执行：


确认输出的是新机器实际登录的微信账号。再做一次小范围拉取：

## 4. 数据库和表结构检查

### 4.1 推荐方式：完整恢复 `crm_me`

使用第 2.2 节的完整备份恢复，不要只导入单个业务 SQL。恢复后检查：

```sql
SHOW CREATE TABLE wechat_message;
SHOW INDEX FROM wechat_message;
SELECT COUNT(*) FROM wechat_message;
```

必须确认 `wechat_message` 存在：

- `content_hash` 生成列；
- `uk_message_identity (username, sort_seq, content_hash)` 唯一键；
- `idx_username_localid (username, local_id)` 普通索引。

如果是从旧版本手工建库、缺少上述结构，先执行修复脚本的只读检查：

```powershell
C:\Software\Python\python.exe .\sql\20261105_wechat_sender_shard_fix.py --dry-run
```

核对重复组后再执行一次：

```powershell
C:\Software\Python\python.exe .\sql\20261105_wechat_sender_shard_fix.py --apply
```

该脚本包含备份和唯一键调整，**不要在没有核对的情况下反复执行**。

### 4.2 不要复用 `server_id` 做单条消息定位

`server_id` 由“会话名 + 会话 ID + 秒级时间戳”组成，同一秒内多条消息可能重复。消息唯一身份应使用：

```text
username + sort_seq + content_hash
```

## 5. 配置定时任务 IP 白名单

白名单校验的是**运行 Java 后端的那台主机**的任意非回环 IPv4，不是浏览器所在电脑的 IP。

### 页面操作

1. 登录新服务器的后台。
2. 进入“系统监控 → 定时任务”。
3. 点击“复制本机IP”，得到新服务器的实际内网 IPv4。
4. 对以下任务逐条编辑，把新 IP 填入“IP白名单”：

| 任务 ID | 任务名称 | 建议白名单 |
|---:|---|---|
| 100 | 微信自动化-消息拉取 | 新服务器 IP |
| 101 | 微信自动化-消息分类 | 新服务器 IP |
| 102 | 微信自动化-TRACE预警 | 新服务器 IP |
| 103 | 微信自动化-历史消息清理 | 新服务器 IP |
| 104 | 微信自动化-INQ/OFFER录入 | 新服务器 IP |
| 105 | 微信自动化-任务生成 | 新服务器 IP |
| 106 | 微信自动化-任务发送 | 新服务器 IP |
| 108 | 好价格Offer-飞书推送 | 新服务器 IP |

任务 107“调度日志清理（保留3天）”当前不限制 IP，可以保持为空；它不是微信业务任务。

5. 多网卡、VPN、动态 IP 场景，把可能用到的本机 IPv4 用英文逗号一起填入。
6. 保存后，先对任务 100 点一次“执行一次”，确认调度日志不再出现“本机IPv4不在白名单”。

### SQL 方式（仅在没有页面时使用）

```sql
UPDATE sys_job
SET allowed_ips = '192.168.128.222'
WHERE job_id IN (100, 101, 102, 103, 104, 105, 106, 108);
```

把示例 IP 替换成新服务器实际 IP。空字符串表示不限制 IP，不建议生产环境这样做。

### 7.2 数据库验收

```sql
SELECT COUNT(*) AS total,
       SUM(sender IS NULL OR sender = '') AS empty_sender,
       SUM(username LIKE '%@chatroom' AND sender = name) AS group_name_as_sender
```

## 8. 分批开启定时任务和业务开关

任务有两个开关层级：

1. `sys_job.status`：定时任务是否触发；`0` 正常、`1` 暂停。
2. `wechat_analysis_config` 字典开关：任务触发后是否真正执行业务。

两层都打开才会执行。不要一次性全部打开。

### 第一阶段：只拉消息

保持暂停：101、102、103、104、105、106、108。

开启：

- 任务 100；
- 字典 `pollEnabled=true`；
- `autoSendEnabled=false`。

验证新消息入库、消息列表、图片/文件详情。建议先手动点“拉取”，确认没有重复消息。

### 第二阶段：分类和 TRACE 预警

开启：

- 任务 101、102；
- `classifyEnabled=true`。

验证：

- 新消息能变成 INQ/OFFER/TRACE/OTHER；
- 我方 `selfNames` 成员消息固定为 OTHER；
- TRACE 飞书预警只在配置的时间范围和冷却规则内发送。

### 第三阶段：INQ/OFFER 录入

开启任务 104 前，先检查供应商映射：

```sql
SELECT dict_label, dict_value
FROM sys_dict_data
WHERE dict_type = 'wechat_analysis_config'
  AND dict_label IN ('offerEntrySupplierCode', 'offerEntrySupplierMap', 'offerEntryEnabled');
```

如果群没有映射且默认供应商为空，录入会跳过。补齐后再设置：

- 任务 104 开启；
- `offerEntryEnabled=true`；
- `autoSendEnabled` 仍保持 `false`。

验证 `crm_offer` 的新增记录、料号、价格、供应商编码和消息关联。

### 第四阶段：任务生成

开启：

- 任务 105；
- `autoTaskGenerateEnabled=true`。

验证任务生成数量、`pending` 原因、审批和编辑。此阶段不要开启自动发送。

### 第五阶段：自动发送

只在以上阶段全部通过后执行：

1. 确认 `autoSendAccount=Eke`。
2. 先用“文件传输助手”做一条单发测试。
3. 检查 `taskSendScanSec`、`taskSendMaxAttempts`、发送批次上限。
4. 开启任务 106；
5. 打开 `autoSendEnabled=true`；
6. 观察前几轮调度日志和任务状态，出现重复发送或失败时立即关闭。

单发测试做法（保持 `autoSendEnabled=false`）：

```powershell
# 用管理账号登录拿 token 后调用
curl.exe -s -X POST "http://localhost:8081/wechat/send" `
  -H "Authorization: Bearer <token>" `
  -H "Content-Type: application/json; charset=utf-8" `
  --data-binary "@wechat_send_test.json"

# wechat_send_test.json（UTF-8，无 BOM）
{"name":"文件传输助手","text":"微信自动化测试"}
```

期望返回：

```json
{"ok":true,"status":"成功","message":"消息已发送并确认：微信自动化测试"}
```

然后查业务库确认落库：

```sql
SELECT id, name, sender, content, create_time
FROM wechat_message
WHERE name = '文件传输助手'
ORDER BY sort_seq DESC
LIMIT 3;
```

`sender` 应为 `Eke`，`content` 与测试文本一致。2026-11-10 实测：发送约 3.8 秒返回成功，消息库 id `649132` 落库。

### 第六阶段：维护类任务

稳定运行后，再开启：

- 任务 103：历史消息清理，保留天数由 `msgRetentionDays` 控制（当前 30 天）；
- 任务 107：调度日志清理，保留最近 3 天；
- 任务 108：好价格 Offer 飞书推送，09:00～21:00 每小时执行。

当前定时任务参考：

| ID | 名称 | Cron | 说明 |
|---:|---|---|---|
| 100 | 微信自动化-消息拉取 | `0/5 * * * * ?` | 实际间隔还受 `pollIntervalSec` 限制 |
| 101 | 微信自动化-消息分类 | `0/10 * * * * ?` | 受 `classifyEnabled`、触发条数和空闲秒数控制 |
| 102 | 微信自动化-TRACE预警 | `0/30 * * * * ?` | 受预警时效、冷却和已告警状态控制 |
| 103 | 微信自动化-历史消息清理 | `0 0 0/6 * * ?` | 受 `msgRetentionDays` 控制 |
| 104 | 微信自动化-INQ/OFFER录入 | `0/10 * * * * ?` | 受 `offerEntryEnabled`、扫描间隔控制 |
| 105 | 微信自动化-任务生成 | `0/10 * * * * ?` | 受 `autoTaskGenerateEnabled` 控制 |
| 106 | 微信自动化-任务发送 | `0/10 * * * * ?` | 受 `autoSendEnabled` 控制 |

## 11. 回滚

## 12. 常见问题

**发言人全是空或显示成别人**

先确认新机器上的微信是否仍有这些历史消息，再执行“修复发言人”。不要手工用群名或 `server_id` 回填。

**定时任务一直不执行**

依次检查：

1. `sys_job.status` 是否为 `0`；
2. `sys_job.allowed_ips` 是否包含后端主机的某个 IPv4；
3. 对应业务字典开关是否为 `true`；
4. 调度日志是否出现“不在白名单”或扫描间隔未到。

**新机器有多个微信账号**

当前 Java 调用网关没有 `--account` 参数，可能自动选错账号。生产主机只保留一个登录账号；多账号排障请手工执行网关命令并显式加 `--account`。

**历史图片/文件打不开**

确认旧 `wechat-gateway\media` 已复制，且 `wechat_message.media_path` 仍指向新机器实际存在的绝对路径。

**自动发送没有执行**

同时检查任务 106 是否正常、`autoSendEnabled` 是否为 `true`、`autoSendAccount` 是否正确，以及任务界面是否有“已审批待发送”的任务。

**发送报 `No module named 'winsdk'`**

Python 3.13+ 没有 `winsdk` 预编译轮子。当前 `wx_gateway.py` 已自动检测并关闭 OCR，正常只会在日志看到提示，不应再把发送任务打成异常。若仍报错，先确认运行的是项目内 `wechat-gateway\wx_gateway.py`。要恢复 OCR 兜底，装 64 位 Python 3.12 和 `winsdk`。

**返回“消息已操作发送，但数据库未确认”**

先到 `wechat_message` 按会话查最新消息，确认是否已经落库。2026-11-10 已修正两个原因：

1. 回读超时从 8 秒放宽到 20 秒，可用环境变量 `WECHAT_VERIFY_TIMEOUT` 调整；
2. 不再用写死的 `sender_id == 2` 判断“自己发的”，改为按当前账号 `username` 匹配。

若仍出现，记录网关日志，并检查微信本地库是否还在正常写入。
