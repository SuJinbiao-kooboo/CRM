# 飞书机器人（Eke）自测文档

本模块位于 `ruoyi-feishu`，随项目启动，使用飞书官方长连接（WebSocket）接入，**无需域名/回调地址**。
提供能力：主动汇报、向用户提问并给 A/B/C/D 选项、接收自定义回答后回后台处理，以及 HTTP 接口控制机器人的开关与消息发送。

---

## 一、飞书开放平台后台配置（一次性）

1. 在 [飞书开放平台](https://open.feishu.cn/app) 打开你的应用，确认已开启【机器人】能力。
2. 事件与回调 → 事件订阅：
   - 接收方式选择 **“使用长连接接收事件”**；
   - 添加事件 **`im.message.receive_v1`（接收消息）**。
3. 权限开通：`im:message`、`im:message:receive`。
4. 将可用范围加入你自己或测试人员。

> 生产环境：国内服务器即可（飞书接口国内可访问），无需部署到境外。

## 二、配置文件

`ruoyi-admin/src/main/resources/application.yml`：

```yaml
feishu:
  enabled: true                     # 是否随项目启动自动开启
  app-id: cli_aa46fffc27b85bd8
  app-secret: FEISHU_APP_SECRET_FROM_ENV
  bot-name: Eke
  domain: https://open.feishu.cn
  report-interval-minutes: 0        # 定时自动汇报间隔（分钟，0=关闭）
  self-test-receive-id: ''          # 自测接收会话 id（可选）
  self-test-receive-type: chat_id   # chat_id / open_id / user_id
```

> **注册指挥 Codex 需要新配置 `feishu.codex.*`**（启用开关、bin、工作目录、沙箱、超时），见 `application.yml` 中 `codex:` 段，默认已开启。

## 三、启动项目

> 先停止旧服务（若 ruoyi-admin.jar 正在运行，需先停掉，否则打包会因文件被占用而失败）。

```bash
# 编译打包（跳过测试）
mvn clean package -DskipTests

# 运行
java -jar ruoyi-admin/target/ruoyi-admin.jar
```

启动后看到日志出现 “飞书机器人已开启（长连接）” 即说明已连上 `wss://msg-frontier.feishu.cn`。

## 四、在飞书里直接对话测试（最直观）

在飞书找到机器人（搜索机器人名称，例如 Eke）并进入单聊：

| 你输入        | 期望行为 |
|---------------|----------|
| `帮助`        | 机器人回复帮助说明 |
| `汇报`        | 机器人发送一份工作汇报 |
| `提问`        | 机器人发送一张带 A/B/C/D 的选择卡片 |
| `A` / `B` / `C` / `D` | 当作选择题选项，转后台任务处理（示例任务） |
| 任意自定义文字 | 自动调用本机 **Codex 实际执行**并回传结果（不再只是示例占位） |
| `codex <指令>` | 调用本机 Codex 非交互执行该指令，并在完成后回传结果（可能要等几分钟） |

## 五、HTTP 接口自测（免登录）

默认端口 `8081`。控制接口类上已加 `@Anonymous`，**免登录、免 token、免权限**，直接用 curl / Postman 调用即可，适合自测与集成。

> 接口入参统一使用 DTO 对象（`FeishuReceiveBody` 及其子类），不再用 Map。公共字段见下表：
>
> | 字段 | 类型 | 说明 |
> |------|------|------|
> | `receiveIdType` | string | 接收者类型：`chat_id` / `open_id` / `user_id`，缺省用配置 `self-test-receive-type` |
> | `receiveId` | string | 接收者 id（会话 id / open_id / user_id），缺省用配置 `self-test-receive-id` |

### 1. 查询机器人状态
```bash
curl -s http://localhost:8081/feishu/bot/status
# 返回 running / enabled / ready / lastError 等
```

### 2. 开启 / 关闭机器人
```bash
curl -s -X POST http://localhost:8081/feishu/bot/start
curl -s -X POST http://localhost:8081/feishu/bot/stop
```

### 3. 发送文本（自测，入参 `FeishuSendTextBody`）
```bash
curl -s -X POST http://localhost:8081/feishu/message/sendText \
  -H "Content-Type: application/json" \
  -d '{"receiveIdType":"chat_id","receiveId":"oc_xxx","text":"你好"}'
```

### 4. 发送 ABCD 选择题卡片（自测，入参 `FeishuSendQuestionBody`）
```bash
curl -s -X POST http://localhost:8081/feishu/message/sendQuestion \
  -H "Content-Type: application/json" \
  -d '{"receiveIdType":"chat_id","receiveId":"oc_xxx","question":"今天先处理哪件事？"}'
```

### 5. 发送工作汇报（自测，入参 `FeishuSendReportBody`，只需接收者信息）
```bash
curl -s -X POST http://localhost:8081/feishu/message/sendReport \
  -H "Content-Type: application/json" \
  -d '{"receiveIdType":"chat_id","receiveId":"oc_xxx"}'
```

### 6. 触发一次 Codex 执行（自测，入参 `CodexRunBody`）
直接在本机调用非交互 `codex exec`，把最终回答回传：
```bash
curl -s -X POST http://localhost:8081/feishu/codex/run \
  -H "Content-Type: application/json" \
  -d '{"prompt":"帮我看看项目里的飞书模块代码结构"}'
```

> 请求体里的参数可省略：缺省时使用配置文件里的 `self-test-receive-id` / `self-test-receive-type`。

### 6. 获取会话 id（chat_id）的方法
给机器人发一条消息，再调用下方接口获取你与机器人的单聊 chat_id：
```bash
curl -s "http://localhost:8081/feishu/bot/status"
```
或在飞书开放平台后台 → 应用 → 调试里查看事件 `im.message.receive_v1` 推送内容中的 `message.chat_id`。
也可以把 `sendText` 的 receiveIdType 改为 `open_id`/`user_id`，直接填你自己的 open_id/user_id。

## 六、权限说明
- 当前所有 `/feishu/**` 接口已通过类上的 `@Anonymous` 注解实现**免登录、免权限**，任何调用方（curl、外系统）都可直接访问，方便自测与集成。
- 若后续想要收紧：移除 `FeishuController` 类上的 `@Anonymous`，在需要的接口方法上加 `@PreAuthorize("@ss.hasPermi('feishu:bot:manage')")` 即可按 RuoYi 标准权限控制。
- 已删除不再使用的权限菜单 SQL `ruoyi-feishu/sql/feishu_menu.sql`。
## 七、接入真实业务
替换以下两个位置的逻辑即可：
- `DefaultTaskExecutor.execute(...)`：处理用户最终选择的 ABCD / 自定义回答的后台任务。
- `FeishuMessageSender.buildReportText()`：工作汇报的真实数据。
- 如需扩展更多消息回调，实现 `FeishuMessageCallback` 并注册为 Spring Bean。
